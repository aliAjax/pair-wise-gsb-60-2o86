# 医疗器械上市后安全信号核查与处置平台

面向医疗器械上市后安全团队的本地工作台，用于合并投诉、维修、不良事件和现场报告，维护证据矩阵、调查任务、风险状态、结论版本和审计轨迹。

## 技术栈

- SvelteKit 2 + Vite + TypeScript
- Skeleton UI + Tailwind CSS
- Svelte stores
- SvelteKit Form Actions
- TanStack Query for Svelte
- Zod

## 主要工作区

- `/`：开放信号、高风险信号、任务和逾期总览
- `/signals`：关键词与多条件筛选、人工登记新信号
- `/signals/[id]`：证据矩阵、状态流转、补充证据、结论版本、重新打开、审计和监管报送件
- `/trends`：发生率趋势与阈值核对
- `/batches`：批号覆盖与报告追踪
- `/regulatory`：监管报送与回执对账（冻结报送、失效补充、提交重试、待核对）
- `/audit`：跨信号审计时间线和 JSON 报告导出

## 监管报送链路规则

- 报送件生成时**冻结**当时的证据矩阵、结论版本和关联批号（含稳定哈希快照）。
- 冻结内容一有变化（补证据、新版本、批号变化），仍有效的原报送件自动**失效**；补充材料**另起一份**补充件，旧件保留可追溯。
- 监管回执按回执号对账：重复回执号只记一次；报送号查无对应或回执指向另一条信号的，先进入**待核对**，人工核对方可挂接。
- 两个窗口同时提交同一条信号的报送时，以 Web Locks 跨窗口互斥保证**先到的生效**；提交失败在原报送件上**就地重试**，不重复生成。
- 旧数据升级时，有结论版本但没有报送件的信号先进入**待补报**，生成补报件后再提交。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18460`。

## 构建与检查

```bash
npm run check
npm run test
npm run build
```

无后端服务，页面使用确定性模拟数据，并将信号、证据、版本和审计记录持久化到浏览器 `localStorage`。关键表单先经过 SvelteKit Form Action 与 Zod 校验，再写入本地 store。
